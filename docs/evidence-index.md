### How the preservation manifests are generated

No script generates them; the recipe is one shell pipeline run from inside the
preserved root. It reproduces `runs/preserved/.manifests/sealed-final-v6.sha256`
and `experiments/autoresearch/raw/.preservation-manifests/public-c4-baseline-v8.sha256`
byte-for-byte:

```bash
LC_ALL=C find . -type f -print0 | LC_ALL=C sort -z | xargs -0 sha256sum
```

`LC_ALL=C` on both the walk and the sort is what makes the ordering stable across
machines. A locale-aware sort reorders paths that differ only in case or
punctuation, producing a file that still verifies but no longer compares equal.

The `e02-dev-a-v6` manifest is the same content in the same order with the `./`
prefix stripped, so reproducing it needs `| sed 's|  \./|  |'` appended. That
difference is cosmetic: `sha256sum --check` resolves both forms against the
current directory, and all three manifests pass. It is recorded rather than
normalized, because rewriting a preservation manifest to tidy a path prefix would
alter custody evidence for no verification gain.

Local custodians can recheck every preserved file without opening its contents:

```bash
(cd experiments/autoresearch/raw/public-c4-baseline-v8 && sha256sum --check ../.preservation-manifests/public-c4-baseline-v8.sha256)
(cd experiments/autoresearch/raw/e02-dev-a-v6 && sha256sum --check ../.preservation-manifests/e02-dev-a-v6.sha256)
(cd runs/preserved/sealed-final-v6 && sha256sum --check ../.manifests/sealed-final-v6.sha256)
sha256sum runs/preserved/sealed-final-v6/score/official_soft_ex/aggregate.json \
  runs/preserved/sealed-final-v6/score/sensitivity/aggregate.json \
  runs/preserved/sealed-final-v6/score/receipt.json \
  runs/preserved/sealed-final-v6/report/held-out-results.md
```
